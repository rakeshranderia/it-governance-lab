# IT Governance Lab

A hands-on learning lab for rebuilding practical technical depth across Linux, web application stacks, Python, APIs, SQL, containers, Terraform and Azure.

## Why this exists

The objective is not to become a full-time software engineer. The objective is to remain technically fluent enough to:

- build and troubleshoot small systems end-to-end;
- understand how application, infrastructure and cloud components interact;
- read and review code/configuration with confidence;
- communicate credibly with engineers and technical specialists;
- maintain hands-on knowledge relevant to senior technology leadership.

## Learning approach

This lab has three tracks:

1. **Build** — create working systems.
2. **Explain** — write ELI5 notes for each major concept.
3. **Evidence** — keep Git history, architecture diagrams, troubleshooting notes and runbooks.

The module numbers are a sequence, not calendar days. Multiple modules can be completed in one session.

## Ground rules

- Prefer building over watching tutorials.
- Break things deliberately and document the fix.
- Use AI as an assistant, but understand every block of code/configuration added.
- Keep Azure spend controlled.
- Commit frequently with meaningful messages.
- Treat commits as part of the learning workflow.
- Document what changed in your understanding.
